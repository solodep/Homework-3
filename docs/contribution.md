# Руководство по внесению вклада

Этот документ описывает процесс разработки и взаимодействия с репозиторием для всех участников команды.

## Процесс внесения изменений

Мы используем Git Flow-подход с главной веткой `main`. Прямые коммиты в `main` запрещены.

1.  **Создание ветки для задачи**
    *   Перед началом работы над новой задачей обновите свою локальную ветку `main` (`git pull origin main`).
    *   Создайте новую ветку от `main`. Используйте соглашение об именовании веток, указанное ниже.
    *   Работайте в своей ветке, делая коммиты.

2.  **Создание Pull Request (PR)**
    *   Когда ваша задача готова, запушите ветку в удалённый репозиторий (`git push origin your-branch-name`).
    *   На GitHub создайте Pull Request из вашей ветки в `main`.
    *   В описании PR четко укажите, что было сделано, какие изменения внесены.

3.  **Процесс ревью и Approve**
    *   **Все PR должны быть одобрены (approved) как минимум N участниками команды**, где N = (общее число участников команды - 1).
    *   Члены команды проводят ревью кода/документов, оставляют комментарии прямо в интерфейсе PR.
    *   Автор PR обязан ответить на комментарии и внести необходимые правки.
    *   Как только собрано необходимое количество апрувов и все обсуждения разрешены, автор PR или любой другой участник может выполнить слияние (Merge) PR в ветку `main`.
    *   После мерджа ваша ветка может быть удалена.

## Соглашения по именованию

### Ветки

Используйте следующий формат: `автор/тип/короткое-описание-задачи`

*   **`автор`** - ваше имя и фамилия через дефис (например: `Antonina-Lapa`)
*   **`тип/`** - тип задачи:
    *   **`feat/`** — для новой функциональности
    *   **`docs/`** — для изменений в документации
    *   **`fix/`** — для исправления ошибок
    *   **`refactor/`** — для рефакторинга
    *   **`style/`** — для изменений форматирования
    *   **`content/`** — для работы с контентом
*   **`короткое-описание-задачи`** - краткое описание задачи на английском или русском, слова разделяются дефисами

**Примеры:**
*   `Alex-Solod/feat/add-customer-questionnaire`
*   `Daniil-Lizunov/fix/typo-in-questionnaire`
*   `Alex-Simonov/docs/update-contributing-guide`
*   `Islam-Adaev/content/add-interview-protocol`

### Коммиты

Сообщения коммитов должны быть на русском или английском языке и кратко описывать суть изменения.

Формат: `[Тип] Краткое описание`

Примеры:
*   `[Docs] Добавлено руководство по контрибьютингу`
*   `[Feat] Добавлены вопросы про безопасность в анкету`
*   `[Fix] Исправлена опечатка в протоколе встречи`

## Система Approve

*   **Цель:** Обеспечить качество кода и документации, а также shared knowledge в команде.
*   **Кто может апрувить:** Любой участник команды, кроме автора PR.
*   **Сколько нужно апрувов:** `N`, где N = (количество участников команды - 1). Это правило настроено в "Branch protection rules" для ветки `main`.
*   **Процесс:** Ревьювер ставит апрув, только если он полностью согласен с изменениями и у него нет замечаний. Если есть замечания, он оставляет комментарий и НЕ ставит апрув до их исправления.
